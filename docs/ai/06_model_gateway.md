# 06 AI 模型网关

## 1. 为什么需要模型网关

业务代码直接调用多个供应商会导致 Key、模型名、重试、计费和错误处理散落。模型网关统一治理：

```text
应用 -> AI Gateway -> OpenAI/百炼/本地 vLLM/其他模型
```

网关负责传输和治理，不应把复杂领域业务塞入路由层。

## 2. 核心能力

- 统一认证、租户和调用方身份。
- 模型别名和 Capability Matrix。
- 按能力、区域、成本、延迟和配额路由。
- 超时、重试、熔断、并发和 Token 限流。
- Prompt/模型版本、Trace 和成本统计。
- 脱敏、内容安全和响应校验。
- 供应商故障时降级或切换。

## 3. Capability Matrix

```json
{
  "modelAlias": "chat-default",
  "provider": "dashscope",
  "model": "qwen-plus",
  "capabilities": ["chat", "stream", "json"],
  "maxInputTokens": 100000,
  "priority": 10
}
```

工具调用、视觉、JSON Schema、长上下文和 Embedding 不能只靠模型别名推断，应配置能力和版本，并在启动/灰度时做 Contract Test。

## 4. 路由策略

```text
请求能力与租户策略
  -> 过滤不支持模型
  -> 过滤区域、合规和配额
  -> 按健康、延迟、成本和优先级打分
  -> 选择主模型
  -> 超时/不可用时选择兼容备用模型
```

备用模型可能不支持相同 Tool/Schema，应提前降级为纯文本、人工或确定性流程，不能盲目重试。

## 5. 限流与预算

维度包括 QPS、并发请求、输入 Token、输出 Token、租户额度、模型额度和每日费用。

```text
入口限流 -> 网关并发信号量 -> Provider QPS/Token 限制
```

队列必须有界，超过容量快速返回排队或降级。Agent 的最大步骤和工具调用也计入预算。

## 6. 重试与幂等

只对连接失败、429 和可恢复 5xx 做有限指数退避；流式生成开始后不应无脑重试。带副作用的 Tool Call 使用 `idempotency_key`，网关保存调用状态但不能代替业务系统的幂等约束。

每次请求传递 Provider Request ID、业务 Trace ID 和调用者 ID，便于供应商工单和内部审计关联。

## 7. 缓存

Cache Key 至少包含：

```text
租户 + 用户权限版本 + 模型 + Prompt 版本 + 输入摘要 + 知识库版本
```

公共事实问答可缓存；个性化、实时价格、权限敏感和副作用结果不要共享缓存。流式响应缓存要处理取消和部分结果。

## 8. 安全边界

- Provider Key 只存在网关，不下发前端。
- 网关清理外部伪造的身份 Header。
- 输入大小、文件类型、URL 和工具参数白名单。
- Prompt 与响应日志脱敏，默认不保存完整内容。
- 供应商返回的 Tool Call 仍需业务 ACL 和 Schema 校验。
- 网络出口、域名、DNS 和证书受到限制。

## 9. 观测

每个 Model Call 记录模型别名、真实 Provider、版本、首 Token、总耗时、输入/输出 Token、状态、重试、费用估算和 Trace ID。高基数 Prompt 只能做哈希或抽样。

告警关注：429、5xx、P99、费用异常、降级比例、结构化解析失败、Provider 路由切换和 Token 爆炸。

## 10. 生产检查清单

- [ ] 模型别名、能力、版本和路由有配置中心与审计。
- [ ] 多供应商降级经过能力兼容测试。
- [ ] QPS、并发、Token 和费用都有硬上限。
- [ ] 重试、熔断、缓存和副作用幂等边界明确。
- [ ] Key、身份、日志、文件和工具都经过安全控制。
- [ ] 每次调用可追踪、可计费、可回放（已脱敏）。
