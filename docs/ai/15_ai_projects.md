# 15 AI 项目实战

## 1. 企业知识库问答

```text
文档采集 -> 解析/切分 -> Embedding -> 向量/关键词索引
用户问题 -> ACL 检索 -> Rerank -> 回答 + 引用
```

重点难点：文档版本、权限、多租户、过期删除、引用校验和 Recall 评估。不要只做“上传 PDF + 相似度搜索”的 Demo。

## 2. 智能客服

分层处理：

```text
意图分类 -> FAQ/RAG
         -> 查询工具
         -> 需要写入或退款 -> 人工审批
         -> 无法解决 -> 转人工
```

客服回答需要知识版本、会话摘要、用户权限、敏感话题拒答和工单关联。转人工要把问题、引用、工具结果和失败原因一并交给坐席。

## 3. SQL 助手

```text
自然语言 -> 选择只读数据集 -> 生成 SQL
         -> SQL Parser/白名单/Explain
         -> 只读账号执行 -> 结果脱敏 -> 解释
```

禁止模型直接使用生产 Root、任意表、写操作和无上限查询。数据库权限、行列权限、最大行数、超时和成本都由服务端控制。

## 4. 代码审查助手

输入代码、Diff、构建结果和规则，输出结构化问题：严重级别、文件行号、原因、证据和建议。模型建议必须经过开发者确认，不能自动修改生产代码或绕过安全扫描。

## 5. Agent 运维助手

只读工具包括查询指标、日志、部署状态和链路；重启、扩容、回滚等操作需要人工审批和变更窗口。每个操作记录操作者、模型建议、工具参数和实际结果。

## 6. 文档抽取流水线

```text
上传 -> OCR/布局 -> Schema 提取 -> 规则校验
     -> 低置信字段人工复核 -> 写入业务表
```

模型提取的金额、日期、合同号和身份信息必须进行类型、范围、校验位和跨字段规则验证。

## 7. 项目架构模板

```text
interfaces
  REST/SSE/WebSocket/Message
application
  Prompt、RAG、Agent、Task、权限编排
domain
  业务规则、状态机、幂等
infrastructure
  Model Gateway、Vector Store、DB、MQ、Object Storage
governance
  Eval、Trace、Cost、Security、Audit
```

模型供应商、向量库和消息队列通过端口适配，业务层不直接依赖某个 SDK。

## 8. 上线最小闭环

1. 明确用户、任务、事实来源和失败边界。
2. 先实现确定性流程，再加入模型节点。
3. 添加 Schema、权限、限流、超时和幂等。
4. 建立脱敏评估集和失败样本收集。
5. 接入 Token/费用/延迟/安全观测。
6. 灰度发布，保留人工接管和回滚。

## 9. 生产检查清单

- [ ] 项目有明确事实数据源和模型不可替代的边界。
- [ ] RAG、Tool、Agent 和工作流权限分层。
- [ ] 副作用支持确认、幂等、审计和补偿。
- [ ] 评估集、灰度、回滚和人工反馈闭环完整。
- [ ] 费用、Token、延迟、质量和安全有预算与告警。
