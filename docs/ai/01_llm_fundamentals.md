# 01 大模型基础

## 1. 大模型应用的基本链路

```text
输入文本 -> Tokenizer -> Token 序列 -> Transformer 推理
        -> 下一个 Token 概率 -> 采样 -> 输出文本
```

大模型本质上根据已有上下文预测后续 Token。它生成流畅内容不代表内容真实，也不会自动访问数据库、互联网或企业知识库。

## 2. Token

Token 是模型处理文本和计费的基本单位，不等于汉字、单词或字符。不同模型的 Tokenizer 不同，同一文本的 Token 数可能不同。

Token 预算包含：

```text
System Prompt
+ 对话历史
+ RAG 文档
+ Tool Schema 与结果
+ 用户输入
+ 模型输出
<= 上下文窗口
```

上下文过长会增加延迟和费用，重要信息也可能被大量噪声淹没。应用应裁剪历史、限制文档数量、压缩工具结果并给输出保留空间。

## 3. 上下文窗口

上下文窗口是单次推理能处理的 Token 上限。支持长上下文不代表模型能同等准确地利用窗口内所有信息。

- 固定 System Prompt 放稳定规则。
- 近期对话保留原文，早期历史使用摘要。
- 大文件使用 RAG，只放相关片段。
- Tool 返回最小必要字段。
- 超限时明确失败或降级，不能静默截断关键指令。

## 4. 生成参数

| 参数 | 作用 | 常见建议 |
|---|---|---|
| Temperature | 调整采样随机性 | 提取、分类使用较低值；创意任务可适当提高。 |
| Top P | 从累计概率范围内采样 | 通常与 Temperature 选一个重点调整。 |
| Max Tokens | 限制最大输出 | 每个接口设置硬上限。 |
| Stop | 遇到指定序列停止 | 防止生成越过协议边界。 |
| Seed | 尝试提高可复现性 | 不保证跨模型版本完全一致。 |

Temperature 不是“智商”参数。业务抽取和工具参数生成需要稳定性，不能通过提高随机性解决准确率问题。

## 5. 消息角色

```text
System：应用规则、角色和安全边界
Developer：应用开发者补充的行为约束
User：用户目标和数据
Assistant：模型历史输出
Tool：应用执行工具后的结构化结果
```

具体角色能力由模型 API 决定。用户输入、文档和工具结果均为不可信内容，不能放到高优先级指令位置。

## 6. 模型类型

| 类型 | 用途 |
|---|---|
| Chat/Reasoning | 问答、分析、生成、工具调用。 |
| Embedding | 将文本转为向量，用于语义检索。 |
| Rerank | 对候选文档重新排序。 |
| Vision | 图片、截图和文档布局理解。 |
| Speech-to-Text | 语音转文本。 |
| Text-to-Speech | 文本转语音。 |
| Moderation | 输入输出内容分类和安全检测。 |

Embedding 和 Rerank 不负责生成最终答案。一个 RAG 系统通常会组合三类模型。

## 7. 幻觉

幻觉是模型生成看似合理但缺少事实依据的内容。原因包括训练知识缺失、问题歧义、错误检索、上下文冲突和模型过度服从“必须回答”。

降低方式：

- 使用 RAG 和可信工具提供事实。
- 要求资料不足时拒答。
- 返回引用并由应用校验引用。
- 使用结构化输出和业务规则。
- 对高风险结果人工复核。
- 建立真实评估集，而不是只优化 Prompt。

无法通过一句“不要幻觉”完全消除幻觉。

## 8. 结构化输出

```json
{
  "intent": "QUERY_ORDER",
  "orderNo": "O20260001",
  "confidence": 0.92
}
```

优先使用模型提供的 JSON Schema/Structured Output 能力。输出解析后仍需校验必填字段、枚举、长度、金额、时间和权限。

模型置信度是模型生成的数值，不应直接当成统计学概率或安全授权依据。

## 9. Tool Calling

模型只生成工具名和参数，应用负责真实执行：

```text
模型选择 query_order
  -> 应用验证 Schema、用户、租户和订单归属
  -> 查询数据库
  -> 返回结果给模型
```

副作用工具需要幂等、确认、审批和审计。模型不能直接持有数据库超级账号或 Shell 权限。

## 10. 模型选择

不要只比较公开 Benchmark。使用自己的业务集评估：

- 任务正确率和结构化输出成功率。
- 中文、代码、长文档和工具调用能力。
- 首 Token、总延迟和并发。
- 输入/输出 Token 单价和缓存策略。
- 数据区域、保留、合规和 SLA。
- 模型版本稳定性与降级能力。

小模型适合分类、路由和抽取，大模型用于复杂推理；使用模型路由比所有任务固定使用最大模型更经济。

## 11. 常见 API 失败

| 类型 | 处理 |
|---|---|
| 400 | 检查参数、上下文、Schema 和模型能力，不重试。 |
| 401/403 | 检查凭据、权限和模型开通，不输出 Key。 |
| 429 | 限流、配额或 Token 超限，带抖动退避。 |
| 5xx | 有限重试或切换模型。 |
| Timeout | 状态未知，Tool 场景防止重复副作用。 |
| Content Filter | 返回安全提示或人工路径，不绕过策略。 |

## 12. 生产检查清单

- [ ] 明确模型、上下文、输出和费用上限。
- [ ] 不把模型输出当作事实、权限或可执行代码。
- [ ] 结构化输出经过 Schema 与业务校验。
- [ ] 工具调用由应用鉴权、执行和审计。
- [ ] 监控 Token、延迟、错误、模型和 Prompt 版本。
- [ ] 具有评估、灰度、降级和安全拒答方案。
