# 03 AI 评估体系

## 1. 为什么必须评估

模型输出具有概率性，同一 Prompt 在模型升级后可能发生变化。AI 应用不能只靠人工演示，需要离线评估、上线灰度和在线反馈形成质量闭环。

```text
数据集 -> 运行候选模型/Prompt -> 自动与人工评分
     -> 对比基线 -> 灰度 -> 在线指标 -> 失败样本回流
```

## 2. 评估对象

| 层次 | 指标示例 |
|---|---|
| 模型调用 | 成功率、延迟、Token、格式成功率。 |
| Prompt 任务 | 分类准确率、提取 F1、摘要完整性。 |
| RAG 检索 | Recall@K、MRR、nDCG。 |
| RAG 生成 | Faithfulness、引用正确、拒答准确。 |
| Agent | 工具选择、参数准确、步骤数、任务完成率。 |
| 安全 | 越权、注入、隐私泄露和危险操作拦截率。 |
| 产品 | 用户完成率、采纳率、人工转接和投诉率。 |

## 3. 评估数据集

数据来源：真实脱敏日志、业务专家编写、历史故障、合成边界样本和攻击样本。

每条样本记录：

```text
input
context/permissions
expected behavior
reference answer or rubric
allowed variations
risk level
tags
```

训练/调试集与最终测试集分离，防止团队针对固定答案过拟合。高风险场景由业务专家标注并定期复审。

## 4. 确定性指标

分类和提取优先使用传统指标：Accuracy、Precision、Recall、F1、Exact Match、JSON Schema Pass Rate。

```text
Precision = 正确预测为正 / 所有预测为正
Recall    = 正确预测为正 / 所有真实为正
```

类目不平衡时不能只看 Accuracy。风控、拒答和越权场景通常更关注 Recall 与漏判成本。

## 5. RAG 评估

检索与生成分开：

- 正确文档未进入 Top K：解析、切分、Embedding 或检索问题。
- 文档正确但回答错误：Prompt、上下文组织或模型问题。

RAG 样本包含有答案、无答案、冲突、过期、越权和引用场景。引用必须验证片段是否真的支持回答。

## 6. LLM-as-a-Judge

使用另一个模型按 Rubric 评分开放式回答：

```text
事实是否由上下文支持：0-2
是否完整回答问题：0-2
引用是否准确：0-2
是否泄露无权限信息：通过/失败
```

风险：评委偏好自身风格、位置偏差、长度偏差和评分漂移。应随机交换候选顺序、隐藏模型名、使用结构化 Rubric，并与人工评分校准。

不能让自动评委独自批准高风险医疗、金融、法律和生产操作。

## 7. Agent 评估

- 是否选择正确工具。
- 参数是否完整且未越权。
- 是否重复执行副作用。
- 是否在步骤/费用上限内完成。
- 工具失败后是否正确恢复或终止。
- 是否在需要时请求人工确认。

Agent 不只评最终答案，还要评整条 Trace 和状态转换。

## 8. 安全红队

测试：直接注入、间接文档注入、编码绕过、角色伪造、跨租户检索、敏感数据套取、工具参数注入、无限循环和费用攻击。

安全样本不能只来自模型自动生成，应结合真实权限模型和历史事故。

## 9. 离线与在线评估

离线评估适合快速回归和版本对比；在线评估观察真实用户行为，但不能把未经验证的高风险模型直接全量 A/B。

上线流程：

```text
离线达标 -> 影子流量 -> 内部用户 -> 小比例灰度
         -> 业务指标与安全监控 -> 扩大或回滚
```

## 10. 回归门禁

按风险设置门槛：

- 核心准确率不得低于基线。
- 越权和危险工具调用必须为零容忍或明确极低上限。
- P95、Token 和费用不得超过预算。
- 结构化输出通过率达到接口要求。
- 模型供应商切换必须通过同一评估集。

## 11. 失败样本闭环

线上失败进入分类队列：检索、Prompt、模型、工具、权限、数据、UI 或用户期望。完成脱敏、标注、修复并加入回归集。

不要只收集“点赞/点踩”，还应提供失败原因选择和人工复核。用户反馈可能带偏见或恶意内容。

## 12. 生产检查清单

- [ ] 具有版本化、脱敏且按风险分层的评估集。
- [ ] 模型、Prompt、RAG、Agent 和安全分别评估。
- [ ] 自动评委与人工标注完成校准。
- [ ] 上线有基线、门禁、灰度和快速回滚。
- [ ] 在线失败能分类、复现并回流回归集。
- [ ] 同时评估质量、延迟、Token、费用和安全。
