# 10 AI 安全

## 1. 威胁模型

AI 应用的攻击面包括用户输入、Prompt、RAG 文档、工具结果、模型输出、第三方模型、插件、日志和训练数据。

```text
不可信输入 -> 模型 -> 工具/数据/系统副作用
       ^                       |
       |------ 数据和指令泄露 --|
```

模型输出不可信，不能直接作为 SQL、Shell、HTML、权限、金额或状态迁移。

## 2. Prompt Injection

- 直接注入：用户要求覆盖系统规则。
- 间接注入：网页、邮件、文档或工具结果包含恶意指令。
- 多轮污染：恶意内容写入 Memory 后影响后续任务。

防护不能只靠 Prompt：应用策略、工具 ACL、数据过滤、沙箱、输出校验、人工审批和审计必须分层。

## 3. 数据泄露

- 输入前按数据等级脱敏和最小化。
- RAG 召回前执行租户/文档 ACL。
- 缓存包含权限和版本维度。
- 日志默认不保存完整 Prompt、Response、Token 和文件。
- 供应商数据保留、训练使用、区域和跨境要求经过评审。
- 删除请求同时处理原文、向量、缓存、日志和备份保留策略。

## 4. 工具安全

```text
模型建议 -> Schema 校验 -> 身份/权限 -> 业务规则 -> 幂等/审批 -> 执行
```

Shell、数据库写入、网络访问、文件读写和支付等工具需要隔离环境、命令/域名白名单、资源上限和完整审计。拒绝工具不能让 Agent 通过另一个工具绕过限制。

## 5. 输出安全

- JSON Schema 和 Bean Validation。
- SQL 使用参数绑定，禁止把模型输出拼入 `${}`。
- HTML/Markdown 在前端进行 XSS 处理。
- URL 使用服务端允许列表，防止 SSRF。
- 文件名、路径、命令、正则和模板做长度和语法限制。
- 金额、库存、权限和状态由确定性代码重新计算。

## 6. 身份与密钥

- API Key、模型私钥、MCP 凭据使用 Secret/KMS。
- 按环境、租户和服务隔离凭据。
- 定期轮换，支持旧新 Key 过渡。
- 生产工具不使用管理员 Token。
- 出站请求经过网关，限制目标域名和端口。

## 7. 供应链

模型权重、Tokenizer、Embedding、Agent 框架和第三方 Tool 都属于供应链：

- 固定版本和 Hash。
- 扫描依赖和镜像漏洞。
- 评估模型 License、数据来源和商业限制。
- 不执行未经审查的模型仓库代码。
- 记录模型、Prompt、工具和知识库版本。

## 8. Red Team 与事故

定期测试越权、数据外泄、注入、无限循环、费用攻击、模型拒答绕过和工具逃逸。事故时撤销凭据、关闭路由、保留 Trace 和审计，再确认影响范围和合规通知，不要只删除日志。

## 9. 生产检查清单

- [ ] 具备输入、检索、工具、输出和日志的分层安全策略。
- [ ] 所有副作用通过确定性 ACL、幂等和审批。
- [ ] RAG/Memory/缓存严格租户隔离。
- [ ] API Key、模型、镜像和工具供应链可追踪。
- [ ] Prompt Injection、SSRF、XSS、SQL 注入和费用攻击有测试。
- [ ] 事故可撤销凭据、回滚模型和追踪影响数据。
