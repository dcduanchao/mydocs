# 11 AI 数据工程

## 1. 数据流水线

```text
数据源 -> 采集 -> 去重 -> 解析/OCR -> 清洗
      -> 分类/脱敏 -> Chunk -> Embedding -> 索引发布
```

每一步都保存状态、版本、错误和重试次数。失败文档进入隔离队列，不应阻塞整个批次，也不能静默丢弃。

## 2. 数据质量

检查：

- 编码、乱码、空文档和重复文档。
- 页眉页脚、导航、代码、表格和图片布局。
- 文档时效、来源、作者和版本。
- Chunk 长度、重叠、标题路径和引用位置。
- 脱敏、密级、租户和 ACL。
- Embedding 模型、维度和索引写入完整性。

建立数据质量指标：解析成功率、有效 Chunk 比例、重复率、最新同步年龄、权限缺失数和向量孤儿数。

## 3. 增量同步

使用来源系统的更新时间、版本号、Webhook、CDC 或定时扫描判断变化：

```text
发现变化 -> 生成新版本 -> 解析/向量化 -> 校验
         -> 原子发布 -> 清理旧版本
```

删除和重命名同样是变更。仅同步新增不处理删除会导致过期知识和越权风险。

## 4. 数据版本与可重建

保存文档 Hash、解析器版本、Chunk 策略、Embedding 模型和索引版本。换模型或切分策略时从原文重建，不从旧向量反推。

```text
knowledge-v1 -> evaluation -> knowledge-v2
                         -> alias/版本切换
```

旧版本保留回滚窗口，确认查询质量和权限后再清理。

## 5. 脱敏与合规

在发送模型前识别手机号、身份证、邮箱、账号、合同和内部密钥。脱敏要保留业务可检索语义，例如用稳定占位符替换姓名而不是全部删除。

原文、脱敏文、向量、缓存、日志和备份分别设置保留和删除策略。仅删除向量不代表数据已从所有系统消失。

## 6. 批处理与任务治理

- 批次有大小、并发和总超时。
- 外部模型 429 使用退避，失败任务可重放。
- 任务使用幂等 `document_id + version`。
- 记录输入、输出、费用和错误，不保存不必要原文。
- 大文件分片处理，避免单任务占满内存。
- 任务完成后校验数量、Hash 和索引状态。

## 7. 数据产品

知识库不是简单文件夹。需要定义 Owner、更新 SLA、权威来源、冲突处理、下线流程、引用展示和用户反馈。没有 Owner 的知识库会快速过期。

## 8. 生产检查清单

- [ ] 采集、解析、清洗、向量化和发布状态可追踪。
- [ ] 新增、修改、删除、重命名均能增量同步。
- [ ] 文档、Chunk、Embedding 和索引版本可重建。
- [ ] ACL、脱敏、保留和删除策略完整。
- [ ] 批量任务幂等、可重试、可暂停和可对账。
- [ ] 知识 Owner、质量指标和更新 SLA 明确。
